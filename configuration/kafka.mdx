# Kafka Consumer

| Env Var | Default | Description |
|---------|---------|-------------|
| `SOURCE_KAFKA_BROKERS` | _(required)_ | Comma-separated Kafka brokers |
| `SOURCE_KAFKA_TOPIC` | _(required)_ | Kafka topic to consume |
| `SOURCE_KAFKA_CONSUMER_GROUP_ID` | _(required)_ | Consumer group ID |
| `SOURCE_KAFKA_CONSUMER_CONFIG_MAX_POLL_RECORDS` | `100` | Max messages returned per poll cycle |
| `SOURCE_KAFKA_POLL_TIMEOUT_MS` | `1000` | How long poll blocks for data |
| `SOURCE_KAFKA_MAX_POLL_INTERVAL_MS` | `300000` | Max time between polls (5 min) before Kafka evicts consumer |
| `SOURCE_KAFKA_SESSION_TIMEOUT_MS` | `10000` | Heartbeat timeout |
| `SOURCE_KAFKA_AUTO_OFFSET_RESET` | `latest` | `latest` or `earliest` |
| `SOURCE_KAFKA_COMMIT_INTERVAL_MS` | `5000` | How often to commit offsets to Kafka |

## Batch-Poll Consumer

Goose uses `ReadMessage` in a loop to poll up to `MAX_POLL_RECORDS` messages per cycle. The first `ReadMessage()` blocks until a message arrives (consumer-group aware, auto-commits handled internally). Subsequent `ReadMessage()` calls use a 100ms timeout via context to collect the remaining messages in the batch. The polled messages are then split into chunks of `WORKER_POOL_SIZE`, and each chunk is dispatched as a separate batch to the worker pool.

<Warning>
Goose uses `ReadMessage` (not `FetchMessage`). The `FetchMessage` API in segmentio/kafka-go blocks forever when a `GroupID` is set — this is a known quirk. `ReadMessage` works correctly with consumer groups.
</Warning>

See [Batch-Poll Consumer](/configuration/batch-poll) for the full chunk-splitting logic, ordered vs multi-worker modes, and benchmark numbers.

<Info>
The `SOURCE_KAFKA_MAX_POLL_INTERVAL_MS` (default 5 minutes) is critical. If processing takes longer than this, Kafka evicts the consumer. Keep `MAX_POLL_RECORDS × HTTP_latency < MAX_POLL_INTERVAL_MS`.
</Info>

## Consumer Groups

Multiple goose pods with the same `SOURCE_KAFKA_CONSUMER_GROUP_ID` share partitions automatically. Different group IDs = independent consumption (each group reads all messages).
