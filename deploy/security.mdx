# Security

Goose is built with production security in mind. Every release includes image signing, SBOM generation, and vulnerability scanning.

## Container Security Context

Every goose pod gets a restrictive security context by default — no configuration needed:

| Setting | Value | Purpose |
|---------|-------|---------|
| `runAsNonRoot` | `true` | Cannot run as root |
| `runAsUser` | `65532` | distroless nonroot UID |
| `readOnlyRootFilesystem` | `true` | No writes to container filesystem |
| `allowPrivilegeEscalation` | `false` | No sudo/privilege escalation |
| `capabilities.drop` | `ALL` | Drop ALL Linux capabilities |
| `seccompProfile` | `RuntimeDefault` | Block unsafe syscalls |

This meets Kubernetes Pod Security Standards **restricted** level.

## NetworkPolicy

Restrict network traffic to/from goose pods:

```yaml
networkPolicy:
  enabled: true
  ingressFrom:
    - podSelector:
        matchLabels:
          app.kubernetes.io/name: prometheus
  egressKafkaPorts: [9092, 9093]
  egressHTTP:
    - ipBlock:
        cidr: 10.0.0.0/8
  egressOTLP:
    - podSelector:
        matchLabels:
          app.kubernetes.io/name: otel-collector
```

| Direction | Allowed | Default |
|-----------|---------|---------|
| Ingress | Prometheus (port 9090) | Configured |
| Egress | DNS (port 53) | Always |
| Egress | Kafka (9092, 9093) | Configured |
| Egress | HTTP sink (80, 443, 8080, 1080) | Configure `egressHTTP` |
| Egress | OTLP collector (4317, 4318) | Configure `egressOTLP` |

<Warning>
You must configure `egressHTTP` with your sink's IP range, or goose won't be able to deliver messages.
</Warning>

## PodDisruptionBudget

Ensure minimum availability during node drains and cluster upgrades:

```yaml
podDisruptionBudget:
  enabled: true
  minAvailable: 1
```

## Cosign Image Signing

All goose Docker images are signed with [Cosign](https://github.com/sigstore/cosign) (sigstore) using keyless signing via GitHub OIDC.

Verify an image before deploying:

```bash
cosign verify ghcr.io/goose-kafka/goose:v1.1.0
```

The signature is stored in the GHCR registry alongside the image. Keyless signing means no private keys to manage — GitHub's OIDC provider proves identity to Sigstore's Rekor transparency log.

## SBOM (Software Bill of Materials)

Each release includes an SPDX JSON SBOM generated by [Syft](https://github.com/anchore/syft):

- Lists every dependency, version, and license in the image
- Available on [GitHub Releases](https://github.com/Goose-Kafka/goose/releases) as `goose-sbom.spdx.json`
- ~785KB for Goose v1.1.0

Use the SBOM to quickly check if a newly announced CVE affects your deployment.

## Trivy Vulnerability Scanning

[Trivy](https://github.com/aquasecurity/trivy) scans run on every CI build and release:

| Scan Type | What | When |
|-----------|------|------|
| Container image | OS packages + Go binaries in Docker image | CI + Release |
| Filesystem | Go source code dependencies | CI |

Results are uploaded as SARIF to the GitHub Security tab. Scans are non-blocking (`exit-code: 0`) — vulnerabilities are reported but don't block releases.

## Dependabot

Goose uses Dependabot for automated dependency updates:

| Ecosystem | Schedule | Grouping |
|-----------|----------|----------|
| Go modules | Weekly (Monday) | All in 1 PR |
| GitHub Actions | Weekly (Monday) | All in 1 PR |
| Docker base image | Weekly (Monday) | Individual PRs |

Updates are labeled `dependencies` and grouped to minimize PR noise.
