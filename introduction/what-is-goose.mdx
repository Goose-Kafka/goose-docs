# What is Goose

> _"Talk to me, Goose." — Maverick, Top Gun (1986)_

Goose is a lightweight, cloud-native Kafka consumer that delivers streaming data to multiple sink types — HTTP REST, gRPC, MongoDB, PostgreSQL, and Redis.

Inspired by **Goose** from _Top Gun_ — the trusted RIO (Radar Intercept Officer) who feeds critical data to Maverick in real-time, never misses a callout, and always has his pilot's back.

<Tip>
  New to Goose? Check out the [Quick Start](/introduction/quick-start) to get running in under 2 minutes.
</Tip>

## What Goose Does

<AccordionGroup>
  <Accordion title="Kafka Consumer">
    Consumes messages from Kafka topics using batch-poll (up to 500 messages per poll cycle). Supports consumer groups for horizontal scaling.
  </Accordion>
  <Accordion title="Schema Conversion">
    JSON passthrough or Protobuf→JSON conversion via Stencil schema registry with long-polling refresh.
  </Accordion>
  <Accordion title="Validation & Filtering">
    CEL-based schema validation ensures message quality. JSONPath and CEL filtering drops unwanted messages before delivery.
  </Accordion>
  <Accordion title="Delivery & Error Handling">
    At-least-once delivery with contiguity-gated offset commits. Config-driven retry → DLQ → circuit breaker. Network errors always retried — zero message drops.
  </Accordion>
  <Accordion title="Observability">
    15 Prometheus metrics, OpenTelemetry traces (consumer + worker spans), Loki log aggregation, and 3 pre-built Grafana dashboards.
  </Accordion>
</AccordionGroup>

## Tech Stack

| Component | Technology |
|-----------|-----------|
| Language | Go 1.27+ |
| Kafka client | segmentio/kafka-go |
| HTTP client | Go net/http (connection pool + TTL) |
| Metrics | Prometheus client_golang |
| Tracing | OpenTelemetry (OTLP gRPC) |
| Filtering | CEL (cel-go) + JSONPath |
| Protobuf | google.golang.org/protobuf (DynamicMessage) |
| Database drivers | lib/pq (PostgreSQL), mongo-driver (MongoDB), go-redis (Redis) |
| Docker | Distroless (~33MB) |
| K8s | Helm chart |

<Callout type="info">
  Goose has 9 dependencies — vs 50+ in Java-based alternatives. No JVM, no classpath issues, no Lombok/Gradle version conflicts.
</Callout>

## Performance

<Callout type="info">
  Benchmarked 2026-09-28 on kind K8s (1 pod, 1 Kafka partition): **6,017 msg/s** at 0ms sink delay, **~4,000 msg/s** at 50ms, **~800 msg/s** in ordered mode (`POOL=1`) — all with **zero drops** and **13–23 MiB** memory. The batch-poll consumer with chunk splitting improved throughput by +60% and cut memory by 23–57% vs the previous baseline. See [Load Test Results](/benchmarking/load-test-results).
</Callout>
