## What Goose Does

Goose is a cloud-native Kafka consumer that delivers streaming data to multiple sink types — HTTP REST, gRPC, MongoDB, PostgreSQL, and Redis — with at-least-once delivery, circuit breaker, schema conversion, and full observability.

<AccordionGroup>
  <Accordion title="At-Least-Once Delivery">
    Contiguity-gated offset commits ensure no message is lost. Network errors are automatically retried. Failed messages go to a Dead Letter Queue (DLQ) for investigation.
  </Accordion>
  <Accordion title="Schema Conversion">
    JSON passthrough for JSON messages. Protobuf→JSON conversion via Stencil schema registry with long-polling refresh — hot-swap descriptors without restart.
  </Accordion>
  <Accordion title="CEL Filtering">
    Filter messages with CEL (Common Expression Language) expressions — Google's modern alternative to JEXL. Supports AND/OR, comparisons, IN, has(), string methods, and nested fields.
  </Accordion>
  <Accordion title="Schema Validation">
    Validate messages with CEL expressions before delivery. Invalid messages go to DLQ — catch bad data at the firehose level, not in your downstream services.
  </Accordion>
  <Accordion title="Circuit Breaker">
    Built-in circuit breaker with sliding window. Opens when failure rate exceeds threshold, pauses outbound calls, probes after timeout, and resumes when the sink recovers.
  </Accordion>
  <Accordion title="Connection TTL">
    Connections are closed after TTL and re-opened, redistributing traffic across backend pods. Fixes the connection pinning bug found in raystack firehose.
  </Accordion>
  <Accordion title="5 Sink Types">
    HTTP REST (individual + batch + batch-with-response), gRPC (raw protobuf passthrough), MongoDB (insert + upsert), PostgreSQL (insert + upsert), Redis (keyvalue + hashset + list).
  </Accordion>
  <Accordion title="Full Observability">
    15 Prometheus metrics, OpenTelemetry traces (Jaeger/Tempo), Loki log aggregation, and 3 pre-built Grafana dashboards.
  </Accordion>
  <Accordion title="Production Hardened">
    Cosign image signing, SBOM (SPDX), Trivy vulnerability scanning, security context (nonroot, readonly FS, drop ALL caps), NetworkPolicy, PodDisruptionBudget, Dependabot.
  </Accordion>
</AccordionGroup>

## Key Metrics

<Callout type="info">
  Goose is ~33MB binary, ~13–23MB RAM under load, <1s startup — 25x smaller than raystack firehose (786MB Java).
</Callout>

| Metric | Goose | Raystack (Java) |
|--------|-------|-----------------|
| Binary size | ~33MB | 164MB jar |
| RAM under load | 13–23MB | ~200–300MB |
| Throughput @50ms sink (1 pod) | ~4,000/s | — |
| Max throughput @0ms (1 pod) | 6,017/s | — |
| Ordered mode throughput | ~800/s | — |
| Message drops | 0 | — |
| Startup | <1s | 5–10s |
| Dependencies | 9 | 50+ |
